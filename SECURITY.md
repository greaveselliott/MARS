# Security Policy

## Supported versions

Once public launch releases exist, only the latest supported MARS release
receives security fixes. During the private launch transition there is no
supported public release; historical tags are not support claims.

## Reporting a vulnerability

Do not open a public issue or Discussion for a suspected vulnerability. Use
GitHub's private vulnerability-reporting form at
<https://github.com/greaveselliott/MARS/security/advisories/new> once the
repository is public and that launch control is enabled.

Include the affected version or commit, impact, safe reproduction steps, and
any suggested mitigation. Remove credentials, private repositories, model
prompts, and unrelated personal data. You should receive an acknowledgement
within seven days. Disclosure timing will be coordinated around a verified
fix and release.

If the private form is unavailable, do not publish exploit details. Use the
repository's **Request a private maintainer contact** issue form, select
**Security reporting form unavailable**, and include no vulnerability details;
the maintainer will arrange a private channel.
